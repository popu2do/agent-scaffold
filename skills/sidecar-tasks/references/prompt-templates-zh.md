# 中文并发子代理模板库

按任务类型选择模板。先替换尖括号变量，再派发。

## 通用派发骨架

```text
任务: <一句话目标>
模型: <默认继承或指定模型>
思考层级: <low | medium | high | xhigh>

第一步:
- 阅读上下文与相关文件: <路径列表>

输入:
- 背景: <业务背景>
- 当前状态: <现状/报错>
- 约束: <性能/兼容/规范>

所有权:
- 你负责: <文件或模块列表>
- 禁止修改: <非职责文件>

约束:
- 你不是唯一在代码库工作的人。
- 不要回退他人的修改。
- 仅在职责范围内改动。

验收标准:
- <标准1>
- <标准2>

验证:
- 执行: <测试/检查命令>

输出:
- 改动摘要
- 修改文件列表
- 验证结果与剩余风险
```

## 模板 A: 日常搬砖 / 快速修 Bug（medium）

```text
任务: 修复 <模块> 的 <问题描述>，保持现有行为边界不变。
模型: <默认继承或指定模型>
思考层级: medium

第一步:
- 阅读并定位问题: <文件1> <文件2>

输入:
- 复现方式: <步骤>
- 期望行为: <期望>
- 实际行为: <实际>

所有权:
- 你负责: <目标文件>
- 禁止修改: <无关模块>

约束:
- 先最小修复，再考虑重构。
- 不引入新依赖。
- 不改公开接口签名（除非明确要求）。

验收标准:
- 能稳定复现并消除该 Bug。
- 不影响现有通过用例。

验证:
- 执行: <最小测试命令>

输出:
- 根因
- 最小修复点
- 测试结果
```

## 模板 B: 重构复杂架构 / 跨文件逻辑（high）

```text
任务: 对 <子系统> 做跨文件重构，目标是 <目标>。
模型: <默认继承或指定模型>
思考层级: high

第一步:
- 建立依赖关系图并识别高风险调用链。

输入:
- 当前痛点: <耦合/重复/性能/可维护性>
- 非目标: <这次不做什么>

所有权:
- 你负责: <模块A> <模块B> <模块C>
- 禁止修改: <外部模块>

约束:
- 先提交重构计划，再执行代码改动。
- 每次改动保持可回归验证。
- 保持向后兼容或明确列出破坏性变化。

验收标准:
- 架构边界更清晰（附简述）。
- 关键路径行为与基线一致。
- 相关测试通过。

验证:
- 执行: <单测命令>
- 执行: <集成测试命令>

输出:
- 分阶段改动说明
- 兼容性影响
- 风险与回滚建议
```

## 模板 C: 简单测试 / 文档注释 / 格式化（low）

```text
任务: 完成 <测试补齐/注释完善/格式化清理>，不改业务逻辑。
模型: <默认继承或指定模型>
思考层级: low

第一步:
- 识别最小必要修改范围。

输入:
- 范围: <文件或目录>
- 风格规范: <lint/doc 规范>

所有权:
- 你负责: <测试或文档文件>
- 禁止修改: <核心业务实现>

约束:
- 只做低风险改动。
- 不引入行为变化。

验收标准:
- 新增或修复的测试可运行。
- 文档与代码一致。
- 格式检查通过。

验证:
- 执行: <pytest/ruff/格式化命令>

输出:
- 修改清单
- 覆盖点说明
- 验证结果
```

## 模板 D: 高难度科研 / 极难算法攻关（xhigh）

```text
任务: 攻关 <算法/研究问题>，在既有方案失败后给出可验证新方案。
模型: <默认继承或指定模型>
思考层级: xhigh

第一步:
- 阅读历史失败尝试与证据，再提出备选策略。

输入:
- 问题定义: <精确定义>
- 历史失败: <尝试1/2/3>
- 成功判据: <正确性/性能阈值>

所有权:
- 你负责: <算法模块与实验脚本>
- 禁止修改: <无关系统模块>

约束:
- 先给策略对比，再选一条实现。
- 每个假设都要可验证。
- 明确复杂度与边界条件。

验收标准:
- 提供至少一个可运行候选方案。
- 与基线对比有量化结果。
- 失败时产出下一轮实验计划。

验证:
- 执行: <基准测试命令>

输出:
- 方案对比表
- 结果数据
- 后续实验建议
```

## 并发拆分模板（主代理使用）

```text
你将接到一个主任务。请拆成可并行子任务，并返回:
1. 子任务列表（每项一句话）
2. 每项建议模型与思考层级
3. 每项文件所有权
4. 是否阻塞主路径（是/否）
5. 建议验证命令

约束:
- 不要产生写入范围重叠的子任务。
- 阻塞主路径的任务不要派发。
- 子任务必须可独立验收。
```

## 集成验收模板（主代理使用）

```text
你将审查多个子代理产出，请完成:
1. 合并风险检查（接口、冲突、行为回归）
2. 验收清单打勾
3. 建议补充测试
4. 最终是否可交付（是/否）与原因

输入:
- 子代理输出摘要: <粘贴>
- 修改文件列表: <粘贴>
- 测试结果: <粘贴>
```
