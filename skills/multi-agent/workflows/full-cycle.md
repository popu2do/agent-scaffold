<required_reading>
执行前必须满足：
- 总指挥持有唯一全局目标与最终裁决权
- 子 Agent 仅处理独立子任务，不做全局裁决
- 验证 Agent 独立于实现路径，不直接接手实现
- 总指挥每轮保留一行状态记录（回复或任务日志均可）
</required_reading>

<process>
## 完整协作流程（主控 + 并行 + 独立验证）

### 阶段 0：冻结目标

总指挥先产出目标快照：
- 目标与非目标
- 约束条件
- 验收标准
- 本轮拆分策略

并写下首条一行状态记录基线。

---

### 阶段 1：并行探索/实现

总指挥拆分 2~N 个可独立完成的子任务，并行派发 Worker：
- Agent3：实现型子任务
- Agent4：文档/契约同步子任务
- Agent1：风险分析或评审型子任务（可选）

```markdown
**任务**: [子任务描述]

**第一步**: 读取角色配置 `.claude/skills/multi-agent/agent[N]-[role].md`

**输入**: [目标快照 + 当前状态 + 子任务输入]

**约束**:
- 不得越界修改
- 不得做全局结论
- 必须返回证据
```

Worker 输出：候选结果 + 证据 + 风险。

---

### 阶段 2：主控汇总

总指挥汇总所有 Worker 输出：
- 合并冲突点
- 标注待验证项
- 形成候选执行结果

并追加一行状态记录：本轮完成项、判断依据、剩余风险。

---

### 阶段 3：独立验证

派发独立验证 Agent（优先 Agent2，必要时 Agent1 复核）：

```markdown
**任务**: 独立验证候选结果

**第一步**: 读取角色配置 `.claude/skills/multi-agent/agent2-gatekeeper.md`

**输入**: [候选执行结果 + 验收标准 + 关键证据]

**输出固定三项**:
1) 错误点
2) 漏项
3) 反例
```

不通过则回到阶段 1 的对应子任务；通过则进入阶段 4。

---

### 阶段 4：结果汇报

总指挥输出最终结论：
- 完成范围
- 验证结果
- 未覆盖风险
- 后续建议（可选）
</process>

<decision_boundary>
## 问题处理与决策边界

| 类别 | 定义 | 处理方式 |
|------|------|----------|
| **业务问题** | 影响交互、默认行为、功能定义 | 上报用户 |
| **技术问题** | 不改变外部行为的内部实现 | Agent 自治 |

```text
遇到决策 -> 是否影响用户行为?
  yes -> 上报用户
  no  -> 在子任务边界内自治
```
</decision_boundary>

<success_criteria>
流程完成标志：
- 目标快照存在且未失焦
- 至少一轮并行子任务执行
- 独立验证输出“错误点/漏项/反例”
- 最终结论由总指挥统一输出
- 状态记录可追溯每轮决策依据
</success_criteria>
