# 流程优化

<standard_output>
为减少 Agent 间理解成本，各阶段输出必须遵循固定格式：

- **标准制定输出（Agent2）**：技术方案 + 验收标准清单（checkbox 格式）
- **实现输出（Agent3）**：实现报告 + 验收标准对照表（标注每项实现位置）
- **独立验证输出（Agent2/Agent1）**：验收结果 + 错误点/漏项/反例
</standard_output>

<incremental_acceptance>
Agent3 实现时采用增量验收：

```
实现功能点1 → 自验收 → 通过 → 实现功能点2 → 自验收 → ...
```

**效果**：
- ✅ 及早发现问题，避免返工
- ✅ 减少独立验证阶段的验收时间
- ✅ 提高实现质量

**操作规范**：
- Agent3 每完成一个验收标准项，立即编写测试并运行
- 测试通过后在验收标准清单中标注 `[x]`
- 全部完成后再提交给 Agent2 验收
</incremental_acceptance>

<parallel_execution>
无依赖的任务可并行派发多个 Agent：

**可并行场景**：
- ✅ 多个独立模块的实现（多个 Agent3）
- ✅ 文档更新与代码验收（Agent4 与 Agent2）
- ✅ 多个独立 Bug 修复（多个 Agent3）

**不可并行场景**：
- ❌ 同一模块的不同功能点（存在依赖）
- ❌ 需要共享状态的任务（配置文件、公共接口）
- ❌ 有先后顺序的任务（先重构再添加功能）
</parallel_execution>
