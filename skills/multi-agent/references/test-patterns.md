# 测试编写模式

<test_structure>
测试分层以仓库既有结构为准。先看仓库里已有什么，再决定写哪一类：
- 单元测试：测试单个函数或类，隔离外部依赖
- 集成测试：测试多个模块协作
- 端到端测试：只有仓库已有该层时才写；仓库没有就不要新造

不要假设存在固定的目录名或测试层级。仓库没有测试设施时，先在汇报里说明，再按项目技术栈补最小可运行测试。
</test_structure>

<test_template>
```
<测试名称>：<被测行为> - <场景>

验收标准：<对应的验收标准编号>

准备：<本次任务的具体前置数据或环境>
执行：<调用被测行为>
断言：<期望结果>
```

语言与测试框架取当前仓库使用的，不使用本文件预设的任何框架。
</test_template>

<coverage_requirements>
- ✅ 功能点：每个功能点至少1个测试
- ✅ 边界条件：每个边界条件至少1个测试
- ✅ 异常场景：每个异常场景至少1个测试
- ✅ 测试命名：清晰描述测试目的
- ✅ 测试文档：每个测试说明其对应验收标准
</coverage_requirements>
