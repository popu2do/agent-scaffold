# 示例

示例中的项目名、版本号、日期与条目内容都只示意结构，成稿时一律替换为本次真实的版本范围与提交证据，不得沿用示例字面量。

## 普通版本

```md
# 示例工具 1.4.0

更新时间：2026-09-01
版本范围：1.3.0 → 1.4.0

## 更新内容

- 页面显示：修复特定场景下内容显示不完整的问题。
- 参数编辑：保存和取消操作在动态内容出现后仍保持可见。
```

## 包含升级事项的版本

```md
# 示例工具 1.5.0

更新时间：2026-10-01
版本范围：1.4.0 → 1.5.0

## 更新内容

- 配置管理：现在可以在设置页直接调整程序级配置。
- 同步预览：同步前会展示本地新增内容及排除内容。
- 依赖识别：本地自带依赖会按实际环境进行识别。

## 升级提示

- 旧版配置会在首次启动时迁移；升级后请确认自定义工具和分组顺序。
```

## 兼容范围收窄

```md
## 更新内容

- 移除旧版配置自动迁移：v1 及更早格式不再自动转换。

## 升级提示

- 使用旧版配置的用户需先转换为当前支持的格式，再升级到本版本。
```

兼容范围收窄时，正文的重点是“移除了什么”和“谁会受到影响”；仍然保留的兼容路径作为补充说明。

## 标题等长（同批条数 ≥ 2 时必做）

同一份正文里所有变化标题取完全相同的汉字数。先确定本批汇总了几条，再统一字数，最后组织每条的措辞；长度不足时不要靠加字凑，而是换一个能说清核心动作的短语。

```md
## 更新内容

- **同步下载提速**：多个文件改为同时下载，不再逐个排队等待。
- **断网自动重试**：此前下载途中断开会直接中止，现在会清理半截文件并重试。
- **超时判定改版**：此前整体等满固定时限就报错，现在按连续无进展判断。
```

三个标题都是 6 个字，左对齐成一块。若把其中一条写成「下载中途断网以后可以自动重试」，长度就与其余两条不齐，需要把它压回 6 字，而不是把另外两条加长。单条版本不存在等长问题。

## 句式示例

推荐：

- `新增配置入口：现在可以直接修改程序级设置。`
- `修复日志采集失败的问题：此前特定路径格式下可能启动失败，现在可以正常启动。`
- `支持新旧入口并行识别：旧入口和新入口都可使用。`

不推荐：

- `整体体验更好了。`
- `内部实现已经统一。`
- `本次完成了大量测试和重构。`

## 提取范围示例

通常保留：

- 设置页新增能力
- 目录或页面导航变化
- 入口兼容和机型适配
- 导入、解析、执行和报告结果变化

通常过滤：

- 版本号提交
- `test(ci)` 和 `fix(ci)`
- 覆盖率补齐
- 纯内部脚本重构
- 权限、门禁和 lint 治理
