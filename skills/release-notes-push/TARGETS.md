# 输出目标说明

## 通用原则

- 所有目标平台使用同一份发布正文，只转换标题、列表、链接等格式。
- 页面默认以版本为单位独立发布，页面标题包含版本标识。
- 首页只维护版本页面入口，避免复制完整正文。
- 远端发布前必须确认平台、页面标识和覆盖策略。

## GitLab Wiki

### 页面规则

- 默认新建独立页面，不直接覆盖 `home`。
- 页面名优先包含版本标识，例如 `release-notes-260706a` 或 `版本更新说明-260706a`。
- 不默认插入 TOC；GitLab 侧边目录已满足常规导航需求。
- 正文较短时直接展示；正文确实较长且需要分层阅读时，才使用 `<details>`。

### 首页入口

```md
# <项目名> Wiki

## 更新说明

- [<页面标题>](<slug>)
```

### 发布脚本

使用 `scripts/publish_gitlab_wiki.py`。

## Confluence

### 页面规则

- 保留标题、版本信息、更新内容和必要的升级提示。
- 使用短段落、列表和加粗表达层级。
- 不使用 GitLab 专属语法，如 `[_TOC_]` 或 `<details>`。

### 发布前信息

- `base-url`
- `spaceKey + ancestorId + title`，或 `pageId`

### 发布脚本

- `scripts/markdown_to_storage.py`
- `scripts/publish_confluence.py`

## 覆盖策略

- 目标页面不存在时创建独立版本页面。
- 目标页面已存在时，按用户确认的策略更新或覆盖。
- 首页入口只在用户确认后新增、替换或删除。
