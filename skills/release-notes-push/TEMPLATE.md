# 更新说明模板

> 这是一份通用发布正文模板。正文只呈现用户需要知道的变化，平台专属语法由目标平台规则处理。

## 默认结构

```md
# <项目名> <版本号>

更新时间：<日期>
版本范围：<起始版本> → <目标版本>

## 更新内容

- <变化标题>：<用户现在能看到或完成的结果>
- <变化标题>：<用户现在能看到或完成的结果>

<!-- 只有存在迁移、兼容条件、额外操作或已知限制时，才保留以下章节。 -->
## 升级提示

- <说明触发条件和用户需要采取的操作>
```

## 编写规则

- `更新内容`通常写 1-4 条，按用户关注度排序。
- 以版本范围起点为主要参照，优先写相对变化；必要时可以用简短背景说明未变化的能力或当前边界。
- 每条只表达一个变化，标题和结果放在同一句中。
- 新功能写“现在可以做什么”。
- 问题修复写“此前会怎样，现在怎样”。
- 兼容范围扩大写新增支持对象；兼容范围收窄突出移除的能力，再按需要补充受影响对象和必要操作。
- 没有升级事项时省略`升级提示`章节。
- 说明内容少时保持简短，不补充内部实现、测试过程或提交分析。
- 只写事实，不使用“更好、更方便、更稳定”等无法单独成立的评价。
- 正文不写路径、模块、脚本、命令、参数或类名，除非读者确实需要技术信息。

## 发布前检查

- 标题、日期和版本范围一致。
- 每条变化都能对应到真实提交或已验证结果。
- 更新内容没有重复表达同一件事。
- 升级提示只包含实际需要用户关注的事项。
